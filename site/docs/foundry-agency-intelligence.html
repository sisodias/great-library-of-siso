The Great Library of SISO · Research operating brief

Foundry Agency Intelligence

Foundry is the source-intelligence engine for discovering what already exists, testing what is actually reusable, and routing proven value to the SISO Work that should own it. SISO Agency OS applies those capabilities to business outcomes. The Great Library keeps the result findable, attributable, and versioned.

Boundary: Foundry remains an independent Research Work and Git repository. The Library records its stable identity, accepted releases, selection history, and promotion candidates. Foundry does not become the system of record for client operations, and the Library does not become a warehouse for Foundry's databases or copied upstream applications.

The application loop

Agency need or industry problem
  → Foundry discovery and direct-source review
  → adoption mode: whole app / API / sidecar / extract / reference / build
  → behavior, integration, cost, and outcome proof
  → Great Library Source Inventory and owner assignment
  → owning Work Release and Library Snapshot
  → Agency OS capability adapter, policy, approval, and audit
  → production evidence returned to Foundry

This loop is the practical link between the Foundry mission, the SISO Library, and the Agency product. It prevents two expensive mistakes: rebuilding mature software from screenshots, and copying source into one giant repository before its ownership and operating boundary are understood.

What has been recovered

A read-only review of the external Foundry data plane observed 1,358,200 repository cards, 23,778 bank repositories, 32,137 ranked liftable candidates, 2,722 adoption decisions, 70 total contract cards with a separately identified 20-card verified subset, a 104-node and 124-edge capability graph, 707 proof selections, 62 agent patterns, 26 prompt records, and 259 repository source signals.

These are 2026-08-02 metadata observations, not current-forever or downloadable-dataset claims. The payload stays external until schema, content-hash, rights, privacy, generator, and durable-copy receipts exist. 879 adoption records remain unresolved.

The Agency portfolio

The recovered application map spans structured work, documents, project delivery, signing, support, scheduling, automation, marketing, analytics, search and AI memory, hosting and data movement, and agent builders. Operator-nominated ideas include Teable, AFFiNE, Open Notebook, Plane, Documenso, Chatwoot, Cal.com, Activepieces, Listmonk, Postiz, Formbricks, Metabase, PostHog, Superset, Meilisearch, Qdrant, RAGFlow, Coolify, Airbyte, dlt, Meltano, Langflow, Coze, and Flowgram.

Those names remain candidates. Stars and open source are nomination signals; adoption requires current revision, license, security, maintenance, tenancy, data ownership, API, deployment, and business-outcome evidence.

The God Source value matrix

Foundry 0.4.0 replaces the repo-list question with a decision unit that can survive different clients and industries: repository × SISO use case × adoption route. A repository can be a God Source for one capability, a platform primitive for another, and the wrong global application shell.

The first cross-agency tranche scores twenty applications from the recovered 9,636-repository evidence universe. It separates gross value from feasibility, then records authority group, agent operations, ownership route, evidence maturity, and the next falsifiable proof gate. Where SISO creates leverage

Source-owned modules already contain years of domain behavior. SISO's compounding IP is the business control plane that lets humans and agents use those modules as one governed operating system:

  • identity, tenant, role, and authority contracts;
  • agent-legible capability and action schemas;
  • approval policy, escalation, and reversible execution;
  • append-only audit, provenance, events, and read models;
  • usage metering, pricing, and entitlements;
  • reliable webhooks and cross-module data contracts; and
  • outcome measurement that improves future Foundry decisions.

The present evidence leaves six high-value control-plane gaps without a proven universal drop-in: usage metering, pricing and entitlements, multi-tenancy, append-only business audit, reliable webhook delivery, and OAuth authority. These are hypotheses for SISO-owned Works, not permission to build before one more focused source sweep.

Evidence discipline

Existing composition experiments support a narrow claim: structured source cards and proven validators can improve steering and catch invalid hand-rolled behavior. They do not prove that arbitrary repositories automatically assemble into a product. Every promotion still needs an owner, an integration boundary, behavior tests, and an outcome receipt.
