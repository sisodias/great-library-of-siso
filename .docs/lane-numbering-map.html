Canonical lane numbering map

Purpose. Three different documents in this estate number the People Graph program lanes, and they disagree. The phrase “Lane 5” resolves to three different bodies of work depending on which document is open. This is a live mis-merge hazard: the schemes are adjacent but offset, so a mix-up selects a real-but-wrong lane rather than failing loudly.

Ruling. Scheme B (parallel-slam, Prompts 1–13) is canonical. It is the only scheme that was actually launched, and every branch, draft PR and handoff in the estate is numbered against it. Schemes A and C are historical and must always be cited with their scheme letter attached.

Citation rule

Write Prompt 5 (B) or simply Prompt 5 for the canonical scheme. Never write a bare lane number when referring to schemes A or C — write Prompt 5 (A, superseded) or Lane 05 (C). A bare number always means scheme B.

The off-by-one that causes the damage

Scheme A opens with Prompt 0, a program coordinator whose PR was to merge before parallel work began. The parallel redesign dropped that coordinator and inserted a new Prompt 1 (Great Library registry spine). The result is a clean one-place shift: A(n) === B(n+1) for n = 1..11.

The consequence is that every number in the range 1–11 is valid in both schemes and points at different work. Two examples that matter most:

  • “Prompt 5” = Reproducible builds and source manifests in B, but Read-only query engine, API/MCP surface, and explorer in A. Both of these lanes exist, both went unshipped, and they own the fixes for two different P0s. Confusing them silently assigns the wrong fix to the wrong defect.
  • “Prompt 12” = Claims, positions, temporal relationships in B, but the adversarial release gate in A. These are not merely different, they are different kinds of work — a content lane versus the program's convergence gate.

Two scheme-A lanes have no scheme-B equivalent

A0 (coordinator) was dropped deliberately. Per prompt-evolution.md, the execution surface was the ChatGPT/Codex web UI, where one chat cannot launch child agents or wait on branch completion. A dependency graph would have idled agents and made a human the scheduler. Dependencies were replaced by exclusive path ownership, current-main starts, additive compatibility shims, and draft-PR handoff — the branches were the orchestrator. That constraint no longer applies.

A12 (adversarial release gate) is the more serious loss. It owned eight named gates including “run Prompt 1's original failure fixtures and prove the selected P0s are resolved” and the rule “do not paper over a red gate”, plus Work registration, immutable Release manifests, the snapshot, and the closing Event. B13 replaced it with a compatibility harness that could run at launch time — correct for the tool constraint, but B13 evaluates compatibility where A12 would have proven the P0s fixed. Nobody currently owns final convergence. The A12 spec survives and is reusable.

Scheme C — first-principles agent program (Lanes 00–12)

Source: docs/first-principles/agent-program.md on branch agent/first-principles-audit-2026-08-06 of sisodias/siso-people-graph.

Scheme C is not a renumbering of A or B. It is an independently derived dependency tree produced by the first-principles re-derivation, with its own decomposition. Do not attempt positional alignment with A or B — there is no consistent offset. It also uses zero-padded two-digit numbering (Lane 00), which is the cheapest way to tell it apart on sight.

Its declared dependency tree:

Lane 00 — Baseline verification and CI
  ├── Lane 01 — Identity safety hotfix
  │     └── Lane 02 — Canonical actor assignments
  │           ├── Lane 03 — Query truth contract
  │           ├── Lane 04 — Temporal semantics
  │           └── Lane 05 — Typed observations
  ├── Lane 06 — Work/version/artifact contract
  │     ├── Lane 07 — Book export boundary
  │     └── Lane 08 — Release protocol
  ├── Lane 09 — Evidence receipt contract
  │     └── Lane 10 — Statement/position pilot
  └── Lane 11 — Source-overlap economics
        └── Lane 12 — Event source pilot

Note the collisions this creates against the canonical scheme: Lane 05 (C) is typed observations and ranking projections, where Prompt 5 (B) is reproducible builds; Lane 07 (C) is the Book export boundary, which is genuinely close in subject to Prompt 7 (B) (Book Library integrity and export) without being the same scope. Near-misses like these are more dangerous than clean mismatches.

Practical guidance during consolidation

  1. When reading any document that says “Lane N” or “Prompt N”, first identify which scheme the document belongs to by its source path, then translate to scheme B before acting.
  2. Zero-padded two-digit numbers (00–12) are always scheme C.
  3. A reference to Prompt 0 is always scheme A — scheme B has no Prompt 0.
  4. A reference to Prompt 13 is always scheme B — only B goes that high.
  5. The two unshipped canonical lanes are B5 (reproducible builds), fixing PG-AUDIT-004/PGRT-001, and B6 (query surface), fixing PG-AUDIT-002/PGRT-004 and PGRT-015. Both have complete work orders in two independent versions (A4+A5 and B5+B6), so they are executable rather than re-derivable.
